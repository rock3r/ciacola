# Animated images (vendored)

Source of Sebastiano Poggi's small animated-image library for Compose Desktop, vendored into
`:deck-effects` (`dev.sebastiano.ciacola.animation`) to play animated WebP and GIF `image` nodes.
GIF decoding uses the JDK's ImageIO reader; animated WebP uses the Skia codec already supplied by
Compose Desktop.

## Changes from the original source

- Package renamed from `animation` to `dev.sebastiano.ciacola.animation`.
- `rememberAnimatedFrame` gained `loop` (default `true`, the original behaviour); `loop = false`
  plays once and holds the last frame.
- Added `animationDurationMs`, `frameIndexAt` (position-to-frame lookup used by Ciacola's own
  beat-driven playhead) and `probeAnimation` (size and frame count without decoding pixels, used by
  lint).
- Tests moved to `deck-effects/src/desktopTest/kotlin/dev/sebastiano/ciacola/animation/`, fixtures
  to `deck-effects/src/desktopTest/resources/animated-images/`. The original build files, Gradle
  wrapper, runnable example and sample generator script are not vendored.

## Playback, limits, and lifecycle

- Frames are immutable full-canvas snapshots. GIF offsets, delta rectangles, clear-to-background
  (transparent), and restore-to-previous disposal are composited before display. WebP offsets,
  blending, and disposal use Skia. WebP decoding requests sRGB color conversion.
- The stored positive frame duration is used; a missing/zero duration becomes **100 ms**. Playback
  repeats indefinitely, intentionally ignoring the file's loop-count metadata. It uses coroutine
  delays, not audio/video synchronization or frame skipping, so a busy UI may slow playback.
- Defaults: **8192 px maximum side**, **24 × 1024 × 1024 total full-canvas pixels**. The pixel budget
  is roughly **96 MiB RGBA**, not a hard process-memory cap: encoded bytes, metadata, working
  canvases, conversion copies, native allocations and renderer textures need additional memory.
  GIF frame descriptors are checked independently so a delta larger than its logical canvas is
  also subject to the limit.
- Excess total animation pixels raise `AnimationTooLargeException` at the low-level API. The loader
  instead shows the first frame with a note, including when an animation exceeds the side limit.
  **The still fallback and still images are not limited by the animation budget.** Use the low-level
  API and refuse over-budget input if an unbounded first-frame decode is unacceptable. No resizing
  is performed.
- This byte-array component does not read files, download URLs, or impose encoded-byte/network
  limits. Bound input size, duration, trust, and concurrent decodes in the host application. It
  decodes every frame up front; it is not a streaming decoder or a sandbox for hostile native data.
- Decode cancellation interrupts between frames, not necessarily during a codec's native call or
  ImageIO metadata scan. ImageIO streams, readers, and temporary Skia codec/data/image/bitmap handles
  are closed. Returned Compose bitmaps are retained normally until their owners release references;
  there is no `close()` method for these values.
- Removing the composable cancels playback and its in-flight load. Re-entry starts at frame zero.
  `playing=false` stops the timer and shows frame zero; it is **not** a resume-at-same-position pause.
  Desktop Compose does not automatically detect viewport occlusion, inactive tabs, minimized
  windows, or application backgrounding. Remove hidden content or pass its visibility/window-active
  state as `playing`. To cancel an in-flight decode as well, remove the loading composition.

## Platforms and versions

- JVM desktop only: Windows x64, macOS arm64/x64, Linux x64/arm64 where the selected Compose/Skiko
  version provides a native runtime. Not Android, browser, Kotlin/Native, or a server-side image API.
- Linux needs a graphical desktop for the example; unit/UI tests run off-screen. Standard AWT,
  fontconfig, and desktop graphics libraries must be installed. Use a full JDK with `java.desktop`.
- The included build and real-window demo were exercised on Debian 13 Linux x64 with JDK 25.0.3.
  Other platforms and JDK 17/21 are compatibility targets, **not tested configurations** in this handoff.
- Only the pinned Kotlin/Compose versions are verified; older/newer Compose APIs are not promised.
  Compile against your application's Compose version when embedding the source.

## Tests and sample media

`./gradlew :deck-effects:desktopTest` exercises both codecs, exact pixel colors/alpha, GIF delta disposal, frame
delays, budget boundaries, interruption, ImageIO cache cleanup, and actual Compose clock-driven
playback/looping/visibility restart. No network service or external media is used by the tests.

The included GIF/WebP files are original geometric fixtures generated by
`examples/generate_samples.py` (not vendored), dedicated to the public domain under CC0-1.0 (see `CC0-1.0.txt` next to the fixtures).
They are not third-party photos or clips. Regeneration is optional and needs Python 3 plus Pillow
12.0.0; running the library/example needs neither. GIF intentionally uses small delta rectangles
and multiple disposal methods; WebP includes transparent pixels and independently timed frames.
